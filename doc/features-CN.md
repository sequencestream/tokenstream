- AI API 接入 — 通过统一网关访问受支持的上游原生 API。
  - OpenAI 兼容接口 — 接入采用 OpenAI 协议的供应商。
    - Chat Completions — 通过 HTTP 或 SSE 转发 `POST /v1/chat/completions`。
    - Responses — 通过 HTTP 或 SSE 转发 `POST /v1/responses`。
    - Responses WebSocket — 通过 `GET /v1/responses` 升级连接进行双向通信。
  - Anthropic 兼容接口 — 接入采用 Anthropic 协议的供应商。
    - Messages — 通过 HTTP 或 SSE 转发 `POST /v1/messages`。
- 透明转发 — 除已配置的模型别名替换外，保留原生流量的应用内容。
  - 流式传输 — 在内存有界的前提下支持长连接流量。
    - HTTP 与 SSE 流式转发 — 以背压方式流式传输请求体和响应体。
    - WebSocket 双向转发 — 在消息大小与队列限制内转发文本和二进制消息。
    - 取消传播 — 客户端断开时取消对应的上游通信。
    - 连接复用 — 复用上游 HTTP 连接，并限制空闲连接数量与存活时间。
  - 协议保真 — 向客户端保留上游协议语义。
    - 路由白名单 — 连接上游前校验供应商协议、方法、路径与传输方式。
    - 原生凭据替换 — 使用 OpenAI Bearer 或 Anthropic `x-api-key` 认证形式替换网关凭据。
    - 请求头与查询串转发 — 保留端到端请求头及原始查询串，同时清理传输相关请求头。
    - 上游响应透传 — 保留上游状态码与响应体，包括错误响应体。
    - WebSocket 握手校验 — 验证上游握手后才接受下游升级，允许客户端自行决定传输回退。
- 供应商管理 — 配置多个上游，并为每个请求确定唯一供应商。
  - 供应商配置 — 由管理员管理共享上游连接。
    - 供应商生命周期 — 创建、列表查询、查看、编辑、启停及删除未被引用的供应商。
    - 端点与上游密钥 — 配置协议、基础端点以及可更换的上游 API 密钥。
    - 受限删除 — 保留被凭据、模型别名或请求日志引用的供应商。
  - 供应商选择 — 从凭据允许的绑定集合中确定上游。
    - 显式选择 — 通过专用请求头选择已绑定到当前凭据的供应商。
    - 默认选择 — 未指定时使用凭据的默认供应商，否则使用有序绑定中的首项。
    - 活跃通信配置稳定 — 配置变更作用于新请求，已准入流保留原配置。
  - 健康与可用性 — 探测已配置的上游，并在不可用时拒绝新请求。
    - 可配置探测 — 设置可选探测路径、间隔、超时及连续失败阈值。
    - 自动隔离与恢复 — 连续探测失败后隔离，一次成功后恢复；低于 500 的状态码视为健康。
    - 手动维护 — 管理员可在计划维护期间拒绝新请求并暂停探测。
    - 健康状态持久化 — 重启后保留健康判定，不中断已准入的流。
- 账号与 API 凭据 — 为每个数据面凭据及请求确定所属账号。
  - 账号管理 — 通过管理员 API 和控制台管理调用方身份。
    - 账号生命周期 — 创建和查看账号，修改名称、密码、角色与启用状态。
    - 两种固定角色 — 区分管理员权限与普通用户对自身凭据、别名和日志的访问权限。
    - 账号停用 — 拒绝已停用账号下所有凭据发起的新流量。
    - 初始管理员 — 初始化管理员账号，并防止其被停用或降级。
  - 凭据生命周期 — 管理账号所属的网关访问密钥。
    - 凭据签发 — 创建密钥，并仅展示一次明文。
    - 原位编辑 — 修改名称、状态、过期时间、供应商绑定、默认供应商和限制，无需更换密钥。
    - 凭据轮换 — 一次性返回替换凭据，并使旧凭据无法认证新请求。
    - 停用与过期 — 拒绝已停用或过期凭据的新认证。
    - 受限删除 — 仅允许删除未被请求日志引用的凭据。
    - 供应商绑定 — 为每个凭据维护有序的允许供应商集合及可选默认项。
- 模型别名 — 使用账号专属名称对应各供应商的上游模型。
  - 别名配置 — 通过校验归属的控制面 API 管理别名。
    - 别名生命周期 — 为有权限访问的账号创建、列表查询、查看、更新和删除别名。
    - 供应商专属目标 — 为同一别名的每个目标供应商配置对应的上游模型名称。
    - 账号隔离与数量上限 — 名称在账号内唯一，每个账号最多保存 100 个别名。
  - 请求模型替换 — 在请求选定供应商后解析别名。
    - HTTP 模型替换 — 在有界请求体前缀与准备时限内，替换一个匹配的顶层 `model` 字符串。
    - WebSocket 模型替换 — 替换客户端文本消息中匹配的顶层模型名称，保留二进制消息与上游消息。
    - 原生模型透传 — 非账号别名的名称原样保留，缺失模型时不补写。
    - 缺失目标拒绝 — 别名未配置所选供应商的目标时拒绝请求，不另选上游。
- 容量与资源保护 — 限制准入流量和资源使用，耗尽时立即拒绝。
  - 分层准入 — 对新请求应用显式配置的传输层限制。
    - 全局并发 — 限制已准入代理通信的总数。
    - 供应商限制 — 为供应商配置可选的并发请求数与请求速率上限。
    - 凭据限制 — 为凭据配置可选的并发请求数、请求速率和长连接 WebSocket 数量上限。
  - 资源预算 — 同时约束转发过程与辅助工作。
    - 监听与传输边界 — 限制已接受连接、HTTP 缓冲、WebSocket 帧、消息及发送队列。
    - 认证隔离 — 为数据面和控制面分别预留密码计算预算。
    - 数据库边界 — 配置连接池容量、认证连接预留及操作时限。
    - 传输时限 — 限制建连、请求与响应头、空闲时间，并可选限制通信总时长。
- 日志与可观测性 — 查看传输元数据，不保留应用载荷。
  - 请求日志 — 尽力记录归属于账号的请求生命周期事实。
    - 元数据记录 — 记录请求标识、账号、凭据、供应商、传输方式、状态、耗时与失败类别。
    - 筛选与游标查询 — 按账号、供应商、传输方式及开始时间范围筛选，并以有界游标分页。
    - 按归属查看 — 普通用户仅查看自身日志，管理员可查看所有账号日志。
    - 非阻塞采集 — 使用有界事件队列与异步批量写入，日志故障不阻塞代理流量。
  - 运行指标 — 在控制面向已认证管理员提供有界的文本指标。
    - 结果与延迟 — 提供通信计数、粗粒度结果、延迟直方图及推导的分位数。
    - 活跃流量与拒绝 — 提供 HTTP、WebSocket 活跃数量及按层级和原因区分的准入拒绝计数。
    - 健康与事件投递 — 提供探测结果、各健康状态的供应商数量，以及订阅者事件投递尝试和丢弃计数。
  - 进程诊断 — 独立于请求日志输出结构化运行事件。
    - JSON 诊断 — 向标准错误输出经过审定的单行 JSON 事件，并支持配置详细程度。
    - 敏感数据排除 — 日志和指标不包含密钥、认证值、查询串及应用载荷。
- 管理与安全 — 为网关配置提供受保护的浏览器和 API 入口。
  - 管理控制台 — 从控制面提供内嵌管理页面。
    - 角色感知视图 — 按登录角色展示凭据、供应商、账号、请求日志和设置。
    - 接入参考 — 展示支持的端点、凭据请求头、占位符 cURL 示例及排障说明。
    - 会话管理 — 支持登录、会话恢复、过期和退出。
  - 访问保护 — 独立于界面控件执行权限校验。
    - 双平面隔离 — 账号会话与数据面凭据不能互相替代。
    - 会话与写入保护 — 使用 HTTP-only、同站 Cookie，生产环境启用 Secure，并对写操作校验 CSRF。
    - 敏感响应保护 — 隐藏已存储的密钥，并禁止缓存管理 JSON 响应。
  - 密钥保护 — 保护静态存储的凭据及维护过程中的密钥。
    - 上游密钥加密 — 使用 AES-256-GCM 加密存储上游 API 密钥，主密钥独立于数据库保存。
    - 密码与凭据哈希 — 保存 Argon2id 哈希，不保存明文密钥。
    - 在线主密钥轮换 — 在读取持续可用时重新加密上游密钥，保留可恢复进度，并在启动前恢复中断的迁移。
- 部署与运行 — 在单个进程中运行网关与管理平面。
  - 持久化配置 — 使用默认值启动并保留操作员变更。
    - 本地零配置启动 — 按默认设置初始化本地存储和密钥。
    - 设置管理 — 通过控制台或 API 查看与修改设置，支持环境变量覆盖和重启提示。
    - 双存储后端 — 使用本地 SQLite 或 PostgreSQL，保持一致的持久化行为。
  - 进程生命周期 — 控制启动、健康检查与关闭。
    - 独立监听 — 分别绑定数据面与控制面地址。
    - 健康端点 — 在两个监听入口提供 `/healthz` 进程健康检查。
    - 启动校验 — 配置无效、必要存储不可用或恢复失败时拒绝启动。
    - 优雅关闭 — 停止接受新连接，在配置时限内排空活跃通信并刷新日志。
  - 分发与兼容性 — 将网关与管理页面一起打包。
    - 跨平台二进制 — 提供 Linux、macOS 的 amd64/arm64 及 Windows amd64 发布包与校验和。
    - 固定版本客户端验证 — 使用固定版本的 OpenAI、Anthropic SDK 和 Codex CLI 验证受支持路由及客户端自主传输回退。
